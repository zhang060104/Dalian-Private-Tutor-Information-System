# 大连家教信息系统数据库设计说明文档

## 运行模式（重要）：

老师&学生通过传单二维码等方式入驻平台后注册个人信息进行老师&学生的双向选择，老师可查看所有的学生（不包含详细地址，名字，联系方式等私密信息）并对自己能胜任的家教投递简历，简历通过后双方缴纳定金（防止单方面逃单）进行订单明细确认，经过双方确定同意后家教老师缴纳信息费获取对方详细信息并安排试课，试课通过则正式开始授课，不通过则退回双方押金的一半以及信息费的一半取消订单（防止刷单）。授课期间双方定金保留防止逃单，可选择私下结算工资或走平台（私下结算需学生方发起私下结算申请教师方进行同意）双方正式确认授课到期后退回全额押金。

**student**(int id , char(16) nickname , char(16) , password , char(11) phone , int age , char(1) gender , int credit , int grade , int subject , text description , int status , int timeTable1 , int timeTable2 , int timeTable3 , int timeTable4 , int timeTable5 , int timeTable6 , int timeTable7  ,  point(SRID 4326) location , text address)

**说明：**

登录使用password+phone登录

gender字段限制为‘男’或‘女’，

subject字段使用二进制编码/解码，约定的科目顺序：

{语文，数学，英语，物理，化学，生物，政治，历史，地理，素描，色彩，速写，乐理，钢琴，吉他，俄语，德语，日语，韩语，编程，算法，心理辅导，体育，自定义}24个科目，subject作为int总共4\*8=32位，截取前面24位作为有效字段，若为1则该学生需要对应科目类型的家教，若为0则不需要。

int timeTable1至timeTable7采用一样的二进制编码思路，timeTable1代表周一的时间表，timeTable2为周二以此类推。32位中一样截取前24位作为有效数据，若为1则代表该天的对应小时空余时间(例如第一位为1时代表该学生在00:00\~01:00时段可以接受家教服务or该老师在00:00\~01:00时段可以提供家教服务)

int grade为0代表幼儿园，1\~6代表小学的1\~6年级，7\~9代表初一\~初三，10\~12代表高一\~高三，13\~16代表大一\~大四，17代表已毕业

description为学生/老师的个人简介，供用户详细说明

int status为0代表正在寻找老师，为1代表已停止寻找老师

text address为学生/老师的地址说明

point(SRID 4326) location为老师/学生的坐标信息，导航系统接入的预留字段。目前计划调用高德地图的接口并进行坐标转换但未完全了解对应技术。如果你们的agent会做的话可以直接做，不会的话暂时作为数据库中隐藏字段为后续拓展定位导航功能预留数据空间

int credit字段为教师方/学生方的信用分，根据往期订单评价以及订单成交情况进行信用分评估，新教师/学生默认100信用分

\*\*备注：\*\*后续数据表中一样的字段采用相同逻辑，有差异会进行说明

**order**(int id , int student\_id , int teacher\_id , int subject , int houly\_wage ,  text depositImgTea , text depositImgStu , text infoFeeImg , text infoFeeQR , text description , int status , int veryfication , int infoFee , int timeTable1 , int timeTable2 , int timeTable3 , int timeTable4 , int timeTable5 , int timeTable6 , int timeTable7)

**说明：**

教师投递简历后或学生指派老师后创建订单，简历被拒绝or超过24小时自动删除（服务器每天00:00进行超时清理）

depositImgTea为教师为该订单缴纳定金的支付截图在服务器中存储的地址

depositImgStu为学生为该订单缴纳定金的支付截图在服务器中存储的地址

infoFeeImg为教师为该订单缴纳信息费的支付截图在服务器中存储的地址

上述支付截图用于管理员核验订单

infoFeeQR为管理员方上传的信息费缴纳收款码

text description为双方的授课服务说明，teacher和student均可进行修改，

int hourly\_wage为授课时薪

int infoFee为我们从中收取的信息费，信息费在老师的简历通过之后从老师方收取，金额为家教授课第一周的工资总额（根据hourly\_wage和timeTable进行计算），只有收取信息费后才会对老师/学生展示对方的联系方式以及地址（防止逃单）

**订单由单方面看中另一方简历信息后发起创建，创建后第二方同意了进入订单明细确认程序，订单信息自动初始化后教师端or学生端均可对订单信息（教授科目，教授时间，description等）进行修改，修改后交由另一方进行审核，审核时可选择再次进行订单信息修改或同意订单，若修改则继续使用修改后的订单信息交由另一方进行审核，同意后进入费用缴纳程序。**

status为0代表该订单刚刚完成简历投递，学生未确认是否接受教师简历。为1代表该订单为学生指派教师创建，教师未确认接受授课。为2代表双方信息订单已确定，正在进入家教订单明细确认程序但没有人对家教订单进行更改。为3代表订单确认后学生端对订单信息进行了修改提交正在等待教师端审核。为4代表订单确认后教师端对订单信息进行修改提交正在等待学生端审核。为5代表双方已完成对对方的简历信息筛选正在缴纳相关费用，并等待管理员核验。

int verification截取前3位二进制编码分别表示教师定金缴纳状态，学生定金缴纳状态，教师信息费缴纳状态

**requestLog**(int id , int type , int tarID , text json)

说明：作为管理员待审核项目的整理表，

int type为0代表教师个人信息修改 , 为1代表学生个人信息修改，为2代表订单-教师定金缴纳核验，为3代表订单-学生定金缴纳核验，为4代表订单-教师信息费缴纳核验

根据int type的值不同，int tarID字段的含义也不同。当type为0时tarID代表修改个人信息的教师id，当type为1时代表修改个人信息的学生id，当type为2\~4时为订单id

json字段包含认证请求对应的信息（如修改后的个人信息或付款截图的文件地址信息）
